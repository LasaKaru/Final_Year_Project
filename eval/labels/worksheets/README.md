# Blind labelling worksheets (Dataset B)

Generated by `python3 scripts/dataset-report.py --worksheets` from the endpoint inventory of each recorded run.
They list every endpoint with an id-like parameter and **do not show the tool's verdict**, so labels are made blind.

For every row, answer from the code at the pinned commit (`../datasets/<case>-<variant>`), not from BolaLens output:

| Column | Question |
|---|---|
| `q1_client_id_selects_object` | Does a value the client controls (route/query/body) select the object that is read or changed? (y/n) |
| `q2_cross_user_effect` | Would that let one ordinary user affect or see **another** user's object if no check existed? (y/n/na — e.g. public data, admin-only) |
| `q3_owner_check_before_effect` | Is there an owner check on the **stored** object (or owner predicate / query filter) before the effect, on every path? (y/n/partial) |
| `label` | `Vulnerable` (q1=y, q2=y, q3=n), `Protected` (q1=y, q2=y, q3=y), `OutOfScope` (q1=n or q2=na), `Unknown` (cannot decide from the code — write why) |

Then copy the decided rows to `eval/labels/<case>-<variant>.labels.json` (format of `fixtures/BolaLab/expected.json`).
Second rater: a random 20 % sample (stratified by your label), labelled independently; report Cohen's κ.
Labels are frozen on **21 Mar 2027**; after that only `eval/labels/CHANGELOG.md` entries explaining a correction are allowed.
